# Recurrent Xylo model: SpiNNaker2 transfer diagnostic

**The existing exact SpiNNaker2 profile cannot preserve this model.** A diagnostic
substitution with the stock SDK's `lif_curr_exp_32bit` runs with the same topology
and all three frozen weight banks, but accuracy falls from 100% to 50%. Spikes,
currents and membrane states differ. This is a failed same-weight transfer,
not a new supported conversion profile or evidence that SpiNNaker2 hardware
cannot implement the model with a custom kernel.

## Experiment

The source is the existing [native recurrent model](README.md): 3 inputs,
24 recurrent hidden neurons, 2 outputs, 40 ticks, thresholds 8 and readout ticks
32–39. The checkpoint and weights are unchanged. All 1,872 held-out sequences
from the same 936 timing templates are evaluated; there is no retraining,
parameter search, weight rescaling or test-based selection.

The diagnostic constructs stock `spinnaker2.snn.Population` and `Projection`
objects and runs the installed `Brian2Backend`. The 32-bit synapse format retains
all int8 source weights, including magnitudes above the ordinary LIF limit.
Each input, readout and recurrent projection is checked against the source
matrix in every independent batch replica. Delays are zero, membrane and
excitatory/inhibitory decay factors are 0.5, and reset subtracts the original
threshold. `t_refract=0` becomes one tick in this SDK. These are a declared
substitution, not an admitted equivalent lowering through AtlasIR.

An observation-only subclass adds excitatory and inhibitory current recording.
The stock equations, event delivery, threshold, reset and execution schedule are
unchanged. The worker receives only the frozen model and input raster, without
labels or reference traces. Effective current is `I_syn_exc - I_syn_inh`.
Neither public package code nor the SDK's neuron-model registry is patched.

The installed versions are spinnaker2 0.8.0, upstream Brian2 2.10.1 and NumPy
2.3.4. Source hashes, executable hashes, weight identity, input identity and raw
result hashes are recorded in the [audit](evidence/spinnaker2/audit.json).
A fresh native evaluation and stock XyloSim rerun establish the reference again.

## Results

| Execution | Correct / 1,872 | Accuracy |
|---|---:|---:|
| Native Atlas, frozen integer model | 1,872 | 100% |
| Stock XyloSim, same model and weights | 1,872 | 100% |
| Stock SpiNNaker2 current-LIF substitution, raw clock | 936 | 50% |
| Same substitution, SDK current-LIF shifted clock | 936 | 50% |

Both SpiNNaker2 views predict class 0 for every input. No output ties or all-zero
readouts occur, so the result is not an `argmax` tie artifact.

The primary comparison uses matching physical ticks 0–39. The SDK's current-LIF
accessors conventionally drop the first voltage and shift event times by one
tick. To check this convention too, the worker runs 41 ticks and reports a
second, predeclared comparison of raw ticks 1–40 against reference ticks 0–39.
Raw monitor timestamps are rounded to clock ticks, avoiding the SDK accessor's
floating timestamp truncation. Both comparisons are retained without choosing
the better one. All state observations are at the end of their respective tick.

| Quantity | Values per comparison | XyloSim differences | SpiNNaker2 raw differences | SpiNNaker2 shifted differences |
|---|---:|---:|---:|---:|
| Hidden/output spike counts | 1,946,880 | 0 | 777,187 | 790,463 |
| Synaptic current | 1,946,880 | 0 | 1,755,891 | 1,771,910 |
| Post-reset membrane | 1,946,880 | 0 | 1,727,071 | 1,751,346 |
| Readout logits | 3,744 | 0 | 2,121 | 2,095 |

The audit also records maximum/mean absolute errors and the first differing
sample, tick and cell. [Per-sample evidence](evidence/spinnaker2/per_sample.npz)

are generated by the reproduction command below and hashed in the audit; they
are not committed.

## Why the current profiles do not match

| Source Xylo integer semantics | Stock SDK current-LIF semantics |
|---|---|
| Integer shift decay with a minimum-decay correction | Floating Euler decay |
| Signed int16 saturation during accumulation and state updates | Unsaturated floating state |
| Hidden spike count 0–31 per tick; output count 0–1 | At most one event per neuron per tick |
| Equality at threshold can spike; reset subtracts `count * threshold` | Strict `v > threshold`; subtracts threshold once |
| Input/previous recurrent counts arrive before the current state update | Groups update before synaptic delivery; current affects a later voltage update |
| One signed integer synaptic-current state | Separate floating excitatory/inhibitory currents |

The trained reference actually produces **255,233 hidden entries above one
spike**, with a maximum of 31. Its spike raster therefore cannot be represented
by a direct one-neuron-to-one-neuron mapping into this binary-event SDK model,
even before considering current rounding or scheduling. Native current ranges
from −129 to 338 here; this test does not isolate saturation as the cause of the
accuracy loss. Several dynamics differences occur together.

The strict `spinnaker2-lif-v1` converter rejects the actual source AtlasIR at the
schedule check. It admits a simpler voltage-only Euler LIF contract; changing
that check would not supply the missing current, count or integer semantics.
The frozen Xylo v2 artifact is also rejected by the native LIF runtime bridge.
Tests retain both boundaries. No supported-target count or profile matrix cell
has been added on the strength of this diagnostic.

A future exact path would need a separately specified and validated integer
neuron implementation, or a proven encoding into supported stock neurons.
Registering a custom application alone is insufficient: this installed SDK's
Brian2 backend has an explicit neuron-model dispatch. Copying the Xylo equations
into a custom Brian2 model would test that extension, not validate stock
SpiNNaker2 dynamics or a hardware deployment. Alternatively, a model can be
trained under a shared supported contract, but that changes the present
same-model/same-weight requirement. None of those paths is claimed here.

## Reproduce

Use the main Atlas environment and isolated SDK environments described in the
parent examples. The native binaries must support the recurrent v2 plan. This
probe evaluates frozen integer weights directly, so it does not restore an
optimizer checkpoint or require the historical training binary identity.

```sh
export PYTHONPATH="$PWD/brian2-rust/python:$PWD"
python brian2-rust/examples/neuromorphic/native_xylo_recurrent/probe_spinnaker2.py \
  --train-runner /path/to/b2-train \
  --runner /path/to/b2-runner \
  --xylo-python /path/to/xylo-env/bin/python \
  --spinnaker2-python /path/to/spinnaker2-env/bin/python \
  --output /tmp/recurrent-spinnaker2-probe
```

The destination must not exist. The command verifies frozen-file identity,
checks strict conversion rejection, reruns native/XyloSim parity, executes the
stock SpiNNaker2 diagnostic and writes `audit.json`, `per_sample.npz`, SDK logs
and complete trace files. `diagnostic_completed=true` means the comparison ran;
`exact_conversion_supported=false` is the result. This software experiment
contains no chip mapping, timing, energy or hardware-accuracy measurement.
